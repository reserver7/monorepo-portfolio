# 보안 이벤트 검토 관리 설계

## 목표

관리자가 보안 이벤트를 단순 조회하는 데서 끝나지 않고 검토 상태, 담당자, 검토 메모를 관리할 수 있게 한다.

## 범위

- 감사 로그에 검토 상태, 담당자, 검토 메모, 검토 시각을 저장한다.
- 기존 감사 로그는 `unreviewed` 상태로 간주한다.
- 관리자만 상태·담당자·메모를 변경할 수 있다.
- 보안 요약에 미검토 고위험 이벤트 수를 표시한다.
- 이벤트 목록에서 상태·위험도·담당자 필터를 제공한다.
- 검토 변경 자체는 별도 감사 이벤트로 기록한다.

## 데이터 모델

`OpsAuditLog`에 다음 필드를 추가한다.

- `reviewStatus`: `unreviewed | in_review | resolved`, 기본값 `unreviewed`
- `reviewedBy`: 검토한 관리자 이메일, nullable
- `reviewNote`: 검토 메모, nullable
- `reviewedAt`: 검토 시각, nullable

Prisma migration으로 적용하며 기존 행은 기본값을 사용한다.

## API

- 보안 이벤트 목록 조회: 상태·위험도·담당자 필터와 페이지네이션
- 보안 이벤트 상태 변경: 상태, 담당자, 메모를 원자적으로 갱신
- 기존 관리자 보안 요약 응답에 `unreviewedHighRiskEvents` 추가

입력 메모는 2~500자로 제한한다. 존재하지 않는 이벤트와 관리자가 아닌 요청은 거부한다.

## UI

- 보안 요약 카드에 미검토 고위험 이벤트 수 표시
- 이벤트 목록에 상태 배지와 담당자 표시
- 상태·위험도·담당자 필터
- 검토 패널에서 상태, 담당자, 메모 저장
- 저장 성공·실패 피드백과 로딩 상태

## 검증

- Prisma migration 적용 및 타입 생성
- 관리자 권한·입력 검증·상태 변경 테스트
- 기존 감사 로그 조회·보안 요약 회귀 테스트
- 웹 타입 검사, i18n 검사, 포맷 및 diff 검사
