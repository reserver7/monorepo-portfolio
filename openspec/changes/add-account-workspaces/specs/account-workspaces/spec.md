## Purpose

계정이 자신의 Collab 문서와 화이트보드를 구분하고 관리할 수 있도록 작업 공간 소유권과 기본 CRUD 동작을 제공합니다.

## ADDED Requirements

### Requirement: 계정 소유권 저장

문서와 화이트보드를 새로 만들 때 시스템은 검증된 OpsLens 계정 식별자를 소유자로 저장해야(SHALL) 합니다. 기존 소유자 정보가 없는 레코드는 시스템 소유 레코드로 취급해야(SHALL) 합니다.

#### Scenario: 새 문서의 소유자 저장

- **WHEN** 인증된 사용자가 문서를 생성합니다.
- **THEN** 문서에는 해당 사용자의 안정적인 계정 식별자가 저장됩니다.

#### Scenario: 기존 레코드 호환

- **WHEN** 소유자 정보가 없는 기존 문서 또는 화이트보드를 읽습니다.
- **THEN** 시스템은 레코드를 손상시키지 않고 시스템 소유 레코드로 처리합니다.

### Requirement: 계정별 목록 조회

인증된 사용자의 문서·화이트보드 목록은 해당 사용자가 소유한 레코드와 시스템 소유 레코드만 포함해야(SHALL) 하며, 다른 계정 소유 레코드는 포함하면 안 됩니다(MUST NOT).

#### Scenario: 다른 계정 데이터 비공개

- **WHEN** 사용자가 작업 공간 목록을 조회합니다.
- **THEN** 다른 계정이 소유한 문서와 화이트보드는 응답에 포함되지 않습니다.

#### Scenario: 시스템 레코드 표시

- **WHEN** 인증된 사용자가 처음 작업 공간 목록을 조회합니다.
- **THEN** 기존 시스템 소유 레코드는 호환성을 위해 목록에 표시됩니다.

### Requirement: 작업 생성

인증된 사용자만 문서와 화이트보드를 생성할 수 있어야(SHALL) 하며, 생성 결과는 요청 사용자의 소유여야(SHALL) 합니다.

#### Scenario: 인증된 생성

- **WHEN** 유효한 세션을 가진 사용자가 제목으로 문서 또는 화이트보드를 생성합니다.
- **THEN** 시스템은 소유자가 현재 계정인 레코드를 만들고 목록에 반환합니다.

#### Scenario: 인증 없는 생성 거부

- **WHEN** 세션이 없거나 유효하지 않은 요청이 생성 API를 호출합니다.
- **THEN** 시스템은 401 응답을 반환하고 레코드를 만들지 않습니다.

### Requirement: 작업 삭제 권한

사용자는 자신이 소유한 문서와 화이트보드를 삭제할 수 있어야(SHALL) 하며, 다른 계정 소유 레코드는 삭제할 수 없어야(MUST NOT) 합니다. 기존 시스템 소유 레코드는 기존 보호 키 정책을 유지해야(SHALL) 합니다.

#### Scenario: 자신의 레코드 삭제

- **WHEN** 소유자가 자신의 레코드 삭제를 요청합니다.
- **THEN** 시스템은 레코드를 삭제하고 성공 응답을 반환합니다.

#### Scenario: 타인 레코드 삭제 거부

- **WHEN** 사용자가 다른 계정 소유 레코드의 삭제를 요청합니다.
- **THEN** 시스템은 403 응답을 반환하고 레코드를 유지합니다.

### Requirement: 인증 정보 보호

HttpOnly Collab 세션 쿠키와 서명 검증에 필요한 비밀값은 브라우저 클라이언트 코드에 노출되면 안 되며(MUST NOT), 소유권 API는 서버 측에서만 계정 식별자를 결정해야(SHALL) 합니다.

#### Scenario: 클라이언트 소유자 위조 방지

- **WHEN** 클라이언트가 다른 계정의 식별자를 요청 본문에 넣어 생성 또는 목록 조회를 시도합니다.
- **THEN** 서버는 요청 본문의 식별자를 무시하고 검증된 세션 계정을 사용하거나 요청을 거부합니다.
