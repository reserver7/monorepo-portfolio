## Why

현재 계정별 목록과 삭제 권한은 분리되어 있지만, 문서 ID를 직접 알고 있으면 상세 API와 실시간 방에 접근할 수 있습니다. 개인 작업 공간을 실제로 안전하게 사용하려면 소유자 중심의 비공개 기본값과 계정별 초대·편집 권한이 필요합니다.

## What Changes

- 문서와 화이트보드에 비공개 기본 접근 정책을 적용합니다.
- 소유자가 이메일 기준으로 계정을 초대하고 `viewer` 또는 `editor` 권한을 부여할 수 있게 합니다.
- 초대된 사용자의 상세 조회, 댓글, 편집, 실시간 참여 권한을 역할에 따라 제한합니다.
- 소유자가 멤버 권한을 변경하거나 초대를 취소할 수 있게 합니다.
- 기존 시스템 소유 레코드와 보호 키 기반 접근은 호환 유지합니다.
- 공개 링크 공유, 팀/조직 관리, 권한 그룹은 이번 범위에서 제외합니다.

## Capabilities

### New Capabilities

- `workspace-sharing`: 계정별 문서·화이트보드 멤버 초대와 역할 기반 접근 제어

### Modified Capabilities

- `account-workspaces`: 개인 소유 레코드의 상세 접근과 편집 권한을 계정 기준으로 확장

## Impact

- Collab 서버의 문서·화이트보드 저장 모델, HTTP API, WebSocket 인증 및 권한 검사
- Collab 웹의 문서·화이트보드 상세 화면과 공유 설정 UI
- OpsLens 세션 브리지의 이메일·계정 식별자 사용
- 기존 JSONB/파일 상태 저장 데이터의 하위 호환 처리
- Supabase 스키마를 별도 테이블로 분리하지 않고 기존 상태 payload에 최소 필드를 추가
