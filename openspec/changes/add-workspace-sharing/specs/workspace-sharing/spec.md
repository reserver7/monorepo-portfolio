## Purpose

개인 작업 공간을 기본적으로 보호하면서 소유자가 필요한 계정만 초대하고, 읽기와 편집 권한을 안전하게 나눌 수 있도록 합니다.

## ADDED Requirements

### Requirement: 비공개 작업 공간

개인 소유 문서와 화이트보드는 인증된 소유자 또는 명시적으로 초대된 멤버만 상세 조회할 수 있어야(SHALL) 합니다. 인증되지 않은 요청과 초대되지 않은 계정은 레코드의 상세 내용, 댓글, 이력에 접근할 수 없어야(MUST NOT) 합니다.

#### Scenario: 초대되지 않은 계정의 상세 접근 차단

- **WHEN** 다른 계정이 개인 문서의 ID를 직접 사용해 상세 조회를 요청합니다.
- **THEN** 서버는 403 응답을 반환하고 문서 내용을 반환하지 않습니다.

#### Scenario: 인증되지 않은 상세 접근 차단

- **WHEN** 세션이 없는 요청이 개인 문서의 상세 API를 호출합니다.
- **THEN** 서버는 401 응답을 반환합니다.

### Requirement: 계정 초대와 역할

소유자는 이메일 주소와 역할(`viewer` 또는 `editor`)을 지정해 계정을 초대할 수 있어야(SHALL) 합니다. 초대된 계정은 세션의 계정 이메일이 초대 정보와 일치할 때만 멤버 권한을 사용할 수 있어야(SHALL) 합니다.

#### Scenario: viewer 초대

- **WHEN** 소유자가 계정 이메일을 `viewer` 역할로 추가합니다.
- **THEN** 해당 계정은 문서를 조회하고 댓글을 작성할 수 있지만 문서 본문과 제목을 변경할 수 없습니다.

#### Scenario: editor 초대

- **WHEN** 소유자가 계정 이메일을 `editor` 역할로 추가합니다.
- **THEN** 해당 계정은 문서를 조회하고 댓글·본문·제목을 변경할 수 있습니다.

#### Scenario: 다른 이메일 세션의 접근 거부

- **WHEN** 초대받은 이메일과 다른 계정이 같은 문서에 접근합니다.
- **THEN** 서버는 초대 권한을 적용하지 않고 403 응답을 반환합니다.

### Requirement: 멤버 권한 관리

소유자는 멤버의 역할을 변경하거나 멤버를 제거할 수 있어야(SHALL) 합니다. 소유자 자신은 멤버 제거 대상이 될 수 없어야(MUST NOT) 합니다.

#### Scenario: 역할 변경

- **WHEN** 소유자가 멤버를 `viewer`에서 `editor`로 변경합니다.
- **THEN** 다음 요청부터 해당 멤버는 편집 권한을 가집니다.

#### Scenario: 멤버 제거

- **WHEN** 소유자가 멤버를 제거합니다.
- **THEN** 해당 계정의 다음 상세·실시간 접근은 403으로 거부됩니다.

### Requirement: 실시간 역할 적용

문서와 화이트보드의 실시간 연결은 HTTP 상세 권한과 동일한 계정·역할을 적용해야(SHALL) 합니다. `viewer`는 읽기 전용으로 연결되고, `editor`와 소유자만 변경 이벤트를 보낼 수 있어야(SHALL) 합니다.

#### Scenario: viewer의 실시간 편집 차단

- **WHEN** viewer 멤버가 실시간 방에 연결한 뒤 변경 이벤트를 보냅니다.
- **THEN** 서버는 변경을 반영하지 않고 권한 거부 이벤트를 보냅니다.

#### Scenario: 제거된 멤버의 재연결 차단

- **WHEN** 제거된 멤버가 새 소켓 연결로 같은 방에 참여합니다.
- **THEN** 서버는 연결 또는 방 참여를 거부합니다.

### Requirement: 기존 레코드 호환

소유자와 멤버 정보가 없는 기존 시스템 소유 레코드는 기존 보호 키와 시스템 레코드 호환 정책을 유지해야(SHALL) 합니다. 새 개인 레코드는 이 예외 정책을 사용할 수 없어야(MUST NOT) 합니다.

#### Scenario: 기존 시스템 레코드 접근

- **WHEN** 인증된 사용자가 기존 시스템 소유 레코드에 접근합니다.
- **THEN** 기존 보호 키가 있으면 보호 키를 요구하고, 없으면 기존 공유 동작을 유지합니다.

#### Scenario: 새 개인 레코드의 보호 키 우회 방지

- **WHEN** 다른 계정이 새 개인 레코드에 기존 editor access key만 제출합니다.
- **THEN** 계정 멤버 권한이 없으면 접근이 허용되지 않습니다.
